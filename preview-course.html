ARCHITECTURE · 02.3RECORDING 6 · 02:04

The problem with local state

Different Pods need access to the same state.

A new client connection may reach a different API Pod. Session preferences held in one Pod’s memory will not automatically be available to another. Valkey makes selected state available to all replicas.

THE DECISIONClient traffic flows through the API Service; state reads and writes originate from the Pods when needed.
✓
HOW YOU KNOW IT WORKED

A state value written by Pod 1 can be read by Pod 3; a stateless request need not touch Valkey.
