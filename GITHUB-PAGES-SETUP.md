# Deploy Containers in Practice to GitHub Pages

This project is the complete **Astro 7.3.8** source repository, not a collection of built HTML files. Use **GitHub Actions** as your Pages publishing source; the Astro build produces the deployable `dist/` directory. Module 4 and the capstone are not implemented yet.

## 1. Prepare the repository

Requirements: a GitHub account; Git; **Node.js 22.12+**; and npm. Extract the ZIP so that `package.json`, `astro.config.mjs`, `src/`, `public/`, and **`.github/workflows/deploy-pages.yml`** are all at your repository root. Hidden `.github` must be included when you upload the project.

Create a new **public** GitHub repository, for example `containers-in-practice`, under the account where you want Pages published. Do **not** select a pre-populated README or template when creating it.

The URL is determined automatically by the actual account and repository (e.g. `https://YOUR-ACCOUNT.github.io/containers-in-practice/`), not by a hard-coded username. A special `YOUR-ACCOUNT.github.io` repository is served at the domain root automatically.

## 2. Install, validate, and lock dependencies

In VS Code / WSL, from the extracted project directory:

```bash
node --version            # Node 22.12+ required
npm install               # generates package-lock.json
npm run check:source
npm run build
npm run check:dist
npm run preview            # http://localhost:4321, after build
```

**Commit `package-lock.json`** generated by `npm install`; the deployment workflow then uses reproducible `npm ci`. If you cannot access npm locally, the workflow can perform an initial install with `npm install`, but reproducibility is not guaranteed until a lockfile is committed.

The self-contained `preview-course.html` is optional for inspecting the layout, but **not** the published site or proof of an Astro build.

## 3. Push source to GitHub

If this directory is not yet a Git repository:

```bash
git init
git branch -M main
git add -A
git commit -m "Prepare Containers in Practice for Pages"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

Replace `YOUR-ACCOUNT` and `YOUR-REPOSITORY` with your own. If the repo already exists locally, do not reinitialize it; copy the contents into the existing repo root and commit/push the changes.

Alternative if using GitHub CLI: `gh repo create YOUR-REPOSITORY --public --source=. --remote=origin --push` (after you have initialized and committed locally).

## 4. Enable Pages

On GitHub, open **Repository → Settings → Pages**. Under **Build and deployment**, choose **Source: GitHub Actions** (not “Deploy from a branch”). The committed `.github/workflows/deploy-pages.yml` runs automatically on every push to `main` and can also be started from the **Actions** tab with **Run workflow**.

Under **Actions**, open **Deploy Containers in Practice**. Wait until the **build** and **deploy** jobs finish successfully. The deploy job's environment URL is the published website URL.

The workflow validates the course source and the generated `dist/` output, including all 11 audio files (one Prerequisites recording + 10 module recordings), the Valkey video, Module 3 field guide, and Module 1 and Module 2 lab downloads.

## 5. Check the published site

After the workflow completes, open the published URL and check:

1. Opening **Check course prerequisites** works, and the 3:31 audio plays.
2. Main narrator starts locked and unlocks after the specified first-click prerequisite action.
3. The pinned controls remain fixed while module navigation scrolls.
4. All narrated modules **00–03** appear and the recordings play.
5. Module 2.3 has the Valkey animation; its resource video loads.
6. Module 2 lab ZIP downloads from its Resources panel.
7. Module 3's Resources (YouTube and official docs) and `/module-3/` page work.

The readiness data is entered by the learner in their browser. No backend or database is required to host this static course.

## Troubleshooting

- **404 on styles/media / blank page:** Confirm **GitHub Actions** is the Pages source, and that `astro.config.mjs` receives the GitHub-provided `GITHUB_REPOSITORY` and `GITHUB_ACTIONS`. It sets `/REPOSITORY/` for project sites automatically.
- **Workflow does not start:** The workflow must be committed at `.github/workflows/deploy-pages.yml` on `main`; check that Actions are enabled for the repository.
- **npm failure / unsupported runtime:** Ensure your local machine uses Node 22.12+; the workflow uses Node 22. Re-run once npm's registry is reachable.
- **First deploy doesn't appear:** Check both jobs in the Actions run and Settings → Pages. GitHub Pages needs the source set to GitHub Actions.
- **Want a custom domain?** Set `ASTRO_SITE` and `ASTRO_BASE` in the build job's `env:` section of the workflow and follow the official GitHub Pages DNS guidance. Do not leave the repository base on a custom-domain root site.

Official reference: https://docs.astro.build/en/guides/deploy/github/
